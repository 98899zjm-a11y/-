# 1.7.0 主机修订36：经审查的维护器源代码差异

本目录只归档此次主机修订36实际使用的六个维护器源文件，保持冻结字节与相对目录。它不是完整运行工程、安装包或新的产品版本，也不能直接覆盖仓库内较早的 `desktop/` 或其他正在开发的候选源码。源文件摘要见 `SOURCE_INDEX.json`。

## 修复范围

1. 旧认证收据可能保留已不存在的历史空目录。新逻辑从全部认证程序及历史文件推导必需父目录，逐组件核验实际路径和物理身份；只有不承载任何必需文件的历史空目录可被省略。目录联接、符号链接、权限错误和祖先竞争仍然拒绝。
2. 预检查失败可能遗留四份原始快照，或已认证的 `source-snapshotted/coreState:null` 五文件记录。新逻辑在当前源程序、原始字节、身份、权限和维护进程条件核验后，同卷原样归档，保留文件及旧收据，允许以新事务重试。未知、部分写入或已进入替换阶段的状态不按空残留处理。

## 依赖与边界

这些文件依赖原冻结维护器的 `project/desktop` 工具、可信发行公钥和签署流程。为避免将未复核的完整运行材料混入源码归档，本目录没有复制运行引擎、安装程序、依赖、签署信封、密钥或业务资料。请维护者结合原受控维护工程使用，不能从本目录单独执行安装。

## 已执行验证

- 六个源文件逐字节匹配实际冻结候选，并通过 Node 语法检查。
- 缺目录、归档/重试、历史恢复及过期边界的相关合同回归通过。真实 Windows 文件系统归档测试也已执行，但其 ACL 和进程调度替身不等于原生安装验收。
- 同一隔离环境实际执行了签署入口的升级中断、原入口恢复及恢复后的升级重试；签名程序、完整程序树、HMAC 启动放行和原快照保全均已独立核验。
- 虚构三库、附件和原钥匙摘要保全已检查。测试登录产生的审计、时长与设备心跳差异保留了原失败/差异结果，再与原一致性备份逐行归因；没有把这些差异改成零变化。
- 正式旧源的缺失空目录形状另以冻结函数做了只读预检，再由原严格安装器执行完整备份、权限验证与升级；正式安装退出0，已安装程序、原程序备份、发行签名、启动及连接服务核验通过。
- 实际收到 DeepSeek 的代码与运行证据审查回复，条件、适用范围和主要开发者裁决均保留于本地工程记录；本源码归档不发布真实日志、生产目录清单、账户信息或签署材料。

以上只证明本批受控的既有1.7.0主机升级路径，不代表首装、真正断电、所有旧版本、所有 Windows 环境、完整财务核算或全部 ERP 功能均已验收。员工修订34更新另有独立交付，不能与主机修订36互换。
