# 点完「检查升级」之后：界面文案对照表

> 适用：1.7.0 员工端「员工一键升级」面板（面板右上角关闭，标题 `员工一键升级`）。
> 用法：在员工机上点完升级按钮，**保持软件开着、不要关窗口**，照下表找到你看到的那一句原文，
> 按「下一步」做，按「要抓的证据」保存东西。
>
> 三条铁律：**不要杀进程**、**不要手工覆盖程序文件**、**不要改注册表**。
> 一键升级会把活交给「更新助手」，它需要软件正常退出才能换文件；你手动杀掉进程，
> 只会让这次升级停在半路，下一次还要人工恢复。

---

## 0. 先确认你看到的是哪个位置

| 位置 | 原文 | 说明 |
| --- | --- | --- |
| 主界面底部 | `总版本 v1.7.0` | 这是**真正的程序版本**，升级前后只认这一行 |
| 主界面横幅 | `发现新版本 <版本号>，可在软件内完成升级。` | 有可用包时出现，带一个 `一键升级` 按钮 |
| 面板标题 | `员工一键升级` | 升级过程都在这个面板里，不要中途关掉 |
| 面板主按钮 | `开始升级` / `检查更新` / `重试升级` | 会随状态变化：出错后变 `重试升级`，已是最新时变 `检查更新` |
| 安装目录 `version` 文件 | `44.9.0` | **不是程序版本**，这是 Electron 引擎版本，别拿它判断升级成没成 |
| 注册表卸载项 DisplayVersion | 可能是 `1.2.0` 之类的旧值 | 安装器写的旧值，**同样不能当程序版本** |

判断"到底升没升"，只认三样：底部 `总版本 v…`、`xjy-install-activation.json` 里的 `programVersion`、
`resources\app.asar` 的 sha256。

## 1. 主表：文案 → 含义 → 下一步 → 要抓什么

### 1.1 正常路径（不是错误）

| 界面文案（原文） | 含义 | 下一步 | 要抓的证据 |
| --- | --- | --- | --- |
| `等待开始升级` / `点击检查升级，软件会自动检查可用版本。` | 还没点 | 点 `开始升级`（或横幅上的 `一键升级`） | 不用抓 |
| `正在检查可用更新` | 正在向主机问"有没有新包" | 等 1~3 秒，别连点 | 不用抓 |
| `已是当前最新版本` + `已安装本次完整员工发布。` | 本机已经是指定版本，主机也没有更大的发布序号 | 正常，说明不需要升级；确认底部 `总版本 v1.7.0` | 跑 `01-check.ps1` 存档（证明是 r2 客户端、asar 哈希对得上） |
| `发现可升级的新版本` + `发现新的完整员工修复，可点击一键升级。` | 主机有更大的发布序号，可以升 | 点 `开始升级` | 升级前先跑一次 `01-check.ps1`，留"升级前"的哈希 |
| `更新包下载中` | 正在下载 `native-package.zip`（几十 MB，慢网络会久） | 等着，不要关面板、不要断网 | 卡超过 10 分钟：`02-collect-logs.ps1` 打包 |
| `正在校验更新包签名和文件` | 下载完在做签名/哈希校验，这一步失败会自动停 | 等着 | 若停在这里并报错，按 1.2 处理 |
| `更新包已校验，可交给更新助手` / `正在交给更新助手` | 马上要交给更新助手，软件会自己退出再启动 | 保存手上的活，让它自己走 | 升级后跑 `01-check.ps1` 留"升级后"的哈希 |
| `更新助手已接收，请等待正常重启` | 更新助手已接手 | **什么都别做**，等它把软件关掉再打开 | 重启后看底部 `总版本`；跑 `01-check.ps1` |

### 1.2 需要处理的提示（员工端能看懂的）

| 界面文案（原文） | 含义 | 下一步 | 要抓的证据 |
| --- | --- | --- | --- |
| `主机尚未发布员工更新包，请继续使用当前程序。` | 主机那边**从来没发布过**员工升级包（发布点没有 `native-manifest.json`），不是本机故障 | 找管理员在主机发布；员工端什么都不用做 | `01-check.ps1`（本机侧）+ 让管理员确认发布目录是否有 `native-manifest.json` |
| `仅员工电脑可以在这里升级，主机请由管理员更新。` | 这台机器的安装身份是**主机（host）**，不是员工机 | 员工机要用员工身份的安装包重装；主机只能由管理员升级 | `01-check.ps1`，看 `install.activationRole` 是不是 `host` |
| `请先使用有效的员工账号登录。` | 没有登录，或登录已过期 | 用员工账号登录后重新点 | 截图 + `01-check.ps1` |
| `升级期间登录账号或会话已变化，请重新检查升级。` | 检查/升级过程中换了账号，绑定关系失效 | 重新点 `检查更新`/`开始升级` | 截图 |
| `本机更新助手尚未安装，当前程序继续可用。` | 安装目录下缺 `受信助手`（更新助手），一键升级没法落地 | 找管理员补装更新助手；当前程序照常可用 | `01-check.ps1`（`install.executables`、`keyFolders` 里有没有 `受信助手`） |
| `本机更新配置尚未核验，当前程序继续可用。` | 更新助手的配置指纹不对（被改动过或版本不匹配） | 管理员重新下发正确配置 | `02-collect-logs.ps1`（含 `受信助手` 目录里的 json） |
| `本机更新助手校验失败，原程序保持不变。` | 更新助手本体校验不过（被替换/损坏） | 管理员重装更新助手；**别自己替换 exe** | `01-check.ps1` + 更新助手文件哈希 |
| `更新下载内容或发布绑定不一致，已停止升级。` | 下载到的包和发布绑定对不上（包被换过、下载截断） | 管理员重新发布；员工端重试 | `02-collect-logs.ps1`（缓存目录里半个包的信息） |
| `本机更新入口已关闭。` | 这台机器上更新入口被策略关掉了 | 管理员确认是否有意关闭 | `01-check.ps1` |
| `本次升级助手尚未停止，请保持当前员工程序打开并联系管理员。` | 上一次的更新助手还在跑，新的进不来 | **保持软件开着**，联系管理员处理，不要杀进程 | 任务管理器截图（只截图，不结束任务）+ `02-collect-logs.ps1` |
| `暂时无法读取升级状态，请稍后重试。` | 面板读状态失败（一般是软件刚起、或 IPC 超时） | 等几秒再点一次；反复出现就打包日志 | `02-collect-logs.ps1` |
| `升级请求未完成，请检查主机连接后重试。原程序保持不变。` | 请求没到主机 / 主机没回（网络、主机没开） | 确认和主机在同一个网、主机上的程序开着 | 截图（含主机地址）+ `02-collect-logs.ps1` |
| `上次完整升级中断。请重新打开已独立审定的一键完整升级.cmd恢复旧程序…` | 上一次升级做到一半断了，需要先恢复 | **按提示找管理员走恢复流程**，不要手工覆盖文件 | 截图 + `01-check.ps1`（`.xjy-patches` 里的记录） |
| `升级未完成，请查看提示后重试。`（状态行） | 面板进入 error 状态，具体原因看上面那句提示 | 按上面那句提示处理；按钮会变成 `重试升级` | 截图 + `02-collect-logs.ps1` |

### 1.3 「不支持」这一类

| 界面文案（原文） | 含义 | 下一步 | 要抓的证据 |
| --- | --- | --- | --- |
| `本机版本尚未提供自动升级入口，请联系管理员。` | 这个安装包**根本不含一键升级功能**（不是 r2 客户端），面板只会说没有入口 | 换 r2 客户端安装包重装；升级功能只有 r2 才有 | `01-check.ps1`：`isR2Client=false`，且 `appAsarSha256` ≠ `9593b161…025a4` |

## 2. 关键陷阱：有一类错误会被"兜底文案"吞掉

面板对**一部分内部错误码没有专门的员工文案**，会统一显示成：

> `本机更新暂不可用，原程序保持不变。`

被吞掉的内部码至少有这些：

| 内部码 | 真实含义 | 谁的问题 |
| --- | --- | --- |
| `BAD_NATIVE_MANIFEST` | 发布包的"身份钉子"不对：目标版本不是 1.7.0、引擎不是 44.9.0、角色不是 employee、平台/架构不是 win32/x64、用途不是员工升级；或同一个包内容被塞进了不同序号 | 主机发布包做错了 |
| `STALE_NATIVE_MANIFEST` | 发布序号**倒退**，或**同一个序号换了包**（序号是单调递增的高水位，不能复用） | 主机发布流程做错了 |
| `EXPIRED_NATIVE_MANIFEST` | 发布包已过期，或发布时间比本机时间超前 5 分钟以上（含本机时钟不对） | 主机重新发布 / 校准时钟 |
| `NATIVE_SOURCE_UNVERIFIED` | 发布来源没通过校验 | 主机发布链 |
| `UPDATE_CHANNEL_UNAVAILABLE` | 更新通道被关 | 主机开关 |

所以：**只要员工看到的是这句兜底文案，界面本身已经不能给出更多信息了**，
必须靠 `01-check.ps1` 的 JSON + 主机侧的发布包比对来定因。这也是本工具包存在的理由。

### 2.1 用证据反推被吞掉的错误码（按顺序走）

1. 打开 `xjy-check.json`，看 `verdict`：
   - `isR2Client=false` → 先别查错误码了，这台机器装的根本不是带升级功能的客户端（见 1.3）。
   - `canUpgradeInApp=false` 而 `isR2Client=true` → 罕见，打包回来人工看。
2. 看 `%APPDATA%\xjy-jewelry-offline\employee-update-cache\` 有没有东西：
   - **整个目录不存在** → 本机从来没成功走到"检查"这一步（请求没到主机 / 主机没发布），
     优先怀疑 `主机尚未发布员工更新包` 或网络问题，而不是 manifest 校验。
   - 目录里有 `native-sequence.json` → 本机确实检查过并记下了"见过的最高发布序号"。
     打开它看序号，和主机发布点比对：
     - 主机 `native-manifest.json` 的序号 **< 本机高水位** → `STALE_NATIVE_MANIFEST`（序号倒退）
     - 序号 **= 本机高水位**，但包内容（`fullTargetCatalogSha256`）变了 → `STALE_NATIVE_MANIFEST`（同序号换包）
     - 序号 **= 本机已装版本且包一致** → 其实这是"已是最新"，不该报错；说明面板显示有误，打包回来
     - 序号 **> 本机**，但包里 `targetVersion`/`engineVersion`/`role`/`platform`/`arch`/`purpose` 有一项不是
       员工升级该有的值 → `BAD_NATIVE_MANIFEST`
     - `expiresAt` 已过，或 `publishedAt` 比本机时间超前 > 5 分钟 → `EXPIRED_NATIVE_MANIFEST`
3. 上面都正常还报兜底文案 → `NATIVE_SOURCE_UNVERIFIED` / `UPDATE_CHANNEL_UNAVAILABLE`，
   交给主机侧查发布开关和签名链。

> 主机发布点（管理员侧，员工机不用碰）：
> `F:\鑫金源珠宝资料\程序设置\员工升级\` 下的 `catalog.json`、`package.zip`、`native-manifest.json`、`native-package.zip`。
> 序号只增不减；要发新的员工包，序号必须比当前高水位大 1 以上。

## 3. 升级成功的三个独立证据（缺一不可）

| 证据 | 升级前 | 升级后 | 在哪看 |
| --- | --- | --- | --- |
| 程序版本 | 旧版本号 | `1.7.0`（底部 `总版本 v1.7.0`） | 界面底部 |
| 安装激活文件 | `programVersion` 旧值 | `programVersion: "1.7.0"` | `<安装根>\xjy-install-activation.json` |
| 客户端哈希 | 旧 asar 的 sha256 | `9593b161f7091f5b471ce4918afee480097105b5668abbe154eb60075b1025a4` | `<安装根>\resources\app.asar`，`xjy-check.json` 的 `verdict.asarSha256` |

补充证据（有则更强）：

- 安装根下 `.xjy-patches\` 多出一个新的 64 位哈希目录（`xjy-check.json` 的 `install.patchAudit` 会列出来）；
- 面板状态停在 `已是当前最新版本`（升级成功后再点检查，正常就显示这个）。

**注意**：升级成功后面板**不会**显示"升级完成"之类的字，它会回到"已是最新"。
所以"看着像没动静"不等于失败，回到界面底部看 `总版本` 才准。

## 4. 看到提示后立刻做的事（顺序别乱）

1. **截图**整个面板（含状态行、提示句、按钮文案）。
2. 不要关软件，不要点第二次。
3. 双击运行 `01-check.ps1`（或右键"使用 PowerShell 运行"），等它打印 `完成 已写入 …\xjy-check.json`。
4. 再运行 `02-collect-logs.ps1`，得到桌面上的 `xjy-logs.zip`。
5. 把 `xjy-check.json`、`xjy-logs.zip`、截图三样一起回传。

如果面板已经把软件重启了（`更新助手已接收`），就等它重启完再做第 3、4 步——
重启后的采集同样有效，只是 `employee-update-cache` 里会多一条高水位记录。

---

## 5. 绝对不要做的事

- ❌ 任务管理器里结束 `鑫金源珠宝报价.exe` / 更新助手进程——会把升级卡在半路。
- ❌ 手工把安装包里的文件复制到安装目录、或删 `resources\app.asar` 再放新的——
  会让激活信息与文件哈希对不上，之后连"检查升级"都会拒绝。
- ❌ 改注册表里的 `DisplayVersion` / `InstallLocation` 想让面板认版本——面板不读这些。
- ❌ 反复连点 `重试升级`——每点一次都会重新下载校验，只会更慢。
- ❌ 把 `.xjy-patches`、`business-data`（客户业务数据）打包外发——采集脚本已排除，手工也别动。
