# 员工机验收工具包（1.7.0 软件内一键升级）

这套东西只干一件事：在**员工电脑**上验证「1.7.0 员工端能不能在软件里自己点一下升级」，
并且在升不上去的时候，留下**看得懂的现场证据**给管理员定位。

工具包不装软件、不改注册表、不动安装目录里的程序文件，只**读**和**打包日志**。
所有产出都在桌面上：`xjy-check.json`、`xjy-logs.zip`。

包里四个文件：

| 文件 | 干什么 | 什么时候用 |
| --- | --- | --- |
| `README.md` | 就是你正在看的这份操作说明 | 开始前读一遍 |
| `01-check.ps1` | 只读采集，生成桌面 `xjy-check.json` | 动升级前后各跑一次 |
| `02-collect-logs.ps1` | 把日志 + 上一步的 json 打成桌面 `xjy-logs.zip` | 出问题时跑 |
| `03-after-click.md` | 点完之后界面上的每一句话是什么意思、下一步做什么 | 看到提示时对照查 |

---

## 一、三步操作

### 第 1 步：先看版本号

打开「鑫金源珠宝报价」，**先别点升级**，看界面**底部（右下角）**的那一行：

```
总版本 v1.7.0
```

把这一行记下来（或者截图）。这是**唯一可信的程序版本**。

> 顺手跑一次采集，留一份"升级前"的现场：
> 在工具包文件夹里，右键 `01-check.ps1` → **使用 PowerShell 运行**，
> 等窗口打印 `完成 已写入 …\Desktop\xjy-check.json` 就可以关掉。
> 不想跑也行，但升级失败时就没法证明"升级前是什么样"。

### 第 2 步：点「检查升级」

在主界面头部点 `一键升级`（有新版时横幅上也有一个同样的按钮），
会弹出标题为 `员工一键升级` 的面板，然后点面板里的按钮：

- 按钮写 `开始升级` → 点它，开始检查并升级
- 按钮写 `检查更新` → 点它（说明上次已经是"最新"状态）
- 按钮写 `重试升级` → 说明上次出错了，先看面板上的提示句，对照 `03-after-click.md` 再决定点不点

点完之后**不要关软件、不要关面板**，看它自己走。正常会依次出现：

```
正在检查可用更新 → 发现可升级的新版本 → 更新包下载中
→ 正在校验更新包签名和文件 → 更新包已校验，可交给更新助手
→ 更新助手已接收，请等待正常重启
```

最后软件会**自己退出再自己打开**，这一步是正常的，让它走完。

### 第 3 步：记录结果

升级流程结束后（或报错停下后），按下面三种结果之一处理。

---

## 二、三种结果，分别该抓什么

| 结果 | 界面上你会看到 | 要抓的东西 |
| --- | --- | --- |
| **A. 已是最新**（没有可升级的包） | 状态行 `已是当前最新版本`，提示 `已安装本次完整员工发布。`，按钮变成 `检查更新` | ①底部 `总版本 v…` 的截图 ②运行 `01-check.ps1`，保留 `xjy-check.json`（用来证明这台是带升级功能的客户端、哈希对得上） |
| **B. 有更新，且升级成功** | 走完下载/校验/交给更新助手，软件自动重启后底部 `总版本 v1.7.0` | ①重启后底部版本截图 ②**再跑一次** `01-check.ps1`（会覆盖上一次的 json，覆盖前把旧的改名成 `xjy-check-升级前.json` 留好）③打开 `xjy-check.json` 确认 `verdict.isR2Client` 是 `true`、`verdict.asarSha256` 是 `9593b161…025a4` |
| **C. 中途报错 / 停在某一步** | 状态行 `升级未完成，请查看提示后重试。`，或一句 `…原程序保持不变。` 之类的提示 | ①**面板整张截图**（要含提示句和按钮文案）②不要关软件，先跑 `01-check.ps1` ③再跑 `02-collect-logs.ps1` 得到 `xjy-logs.zip` ④三样一起回传，并把你看到的提示句原文抄一遍 |

> 特别注意：如果提示是 **`本机更新暂不可用，原程序保持不变。`**，
> 说明界面把真正的错误原因吞掉了（发布包序号、身份校验、过期等都会被折成这一句）。
> 这属于"必须靠证据定因"的情况——`xjy-check.json` 一定不能漏。
> 具体怎么反推，见 `03-after-click.md` 第 2 节。

## 三、采集脚本怎么用

两个脚本都是**只读**的，不需要管理员权限，跑完直接把窗口关掉就行。

最省事的用法：在工具包文件夹里**按住 Shift 右键 → 在此处打开 PowerShell 窗口**，然后：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\01-check.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\02-collect-logs.ps1
```

也可以直接右键脚本 → **使用 PowerShell 运行**（有些机器默认关联到记事本，那就用上面的命令）。

跑完桌面会多出两个文件：

| 文件 | 内容 | 大概多大 |
| --- | --- | --- |
| `xjy-check.json` | 机器/用户/SID、安装根判定、程序版本、`app.asar` 的 sha256、是不是 r2 客户端、最近的升级日志与 JSON、`%ProgramData%` 下的审定目录、结论 `verdict` | 几十 KB |
| `xjy-logs.zip` | 上一步的 json + 所有采到的文本日志 + 一份 `manifest.txt`（说明采了什么、跳过了什么） | 几十 KB ~ 几 MB |

常用参数：

```powershell
# 日志往前多看 60 天
powershell -NoProfile -ExecutionPolicy Bypass -File .\01-check.ps1 -LogDays 60

# 指定输出位置（默认桌面）
powershell -NoProfile -ExecutionPolicy Bypass -File .\01-check.ps1 -OutFile D:\xjy-check.json
powershell -NoProfile -ExecutionPolicy Bypass -File .\02-collect-logs.ps1 -OutZip D:\xjy-logs.zip
```

`02-collect-logs.ps1` 会自动读取桌面上的 `xjy-check.json`；找不到就自己重新扫一遍，
但那样证据会少一些，所以**顺序是先 01、再 02**。

## 四、三个铁律（违反会制造更难查的问题）

1. **不要杀进程。** 一键升级是把活交给"更新助手"，它要靠软件正常退出才能换文件。
   任务管理器里结束 `鑫金源珠宝报价.exe` 或更新助手，会把升级卡在半路，下次还得人工恢复。
2. **不要手工覆盖程序。** 别把安装包里的文件复制进安装目录，别删 `resources\app.asar` 再塞新的。
   文件一换，激活信息和哈希就对不上，之后连"检查升级"都会拒绝，只能重装。
3. **不要改注册表。** 面板不读注册表的 `DisplayVersion`，改了只会误导后面排查的人。

另外：采集脚本**不会**碰客户业务数据（`business-data`、`.xjy-patches`、`内帐` 数据库、Excel、备份 zip），
这些在脚本里是按路径和类型双重排除的——这也是为什么 `xjy-logs.zip` 通常只有几十 KB。

## 五、几个容易误读的地方

| 你可能以为 | 实际 |
| --- | --- |
| 安装目录 `version` 文件写着 `44.9.0`，所以程序是 44.9.0 | 错。`version` 是 **Electron 引擎版本**，不是程序版本。程序版本看底部 `总版本 v…` 和 `xjy-install-activation.json` 的 `programVersion` |
| 控制面板"程序和功能"里显示 `1.2.0`，版本很旧 | 这是安装器写死的旧值，**不可信**，面板判断版本根本不看它 |
| 点了按钮没反应 | 先看面板状态行那行字，再对照 `03-after-click.md`。多数是"已是最新"或"主机没发布员工包"，不是坏了 |
| 升级完面板没提示"升级成功" | 正常。升级成功后它只会回到"已是最新"，判断成功要回到底部看 `总版本` |
| 主机上也能点一键升级 | 主机（`role: host`）不能在这里升级，会提示 `仅员工电脑可以在这里升级，主机请由管理员更新。` |

## 六、回传清单

出错时把这三样发给管理员，缺一样都可能要多跑一趟：

1. 面板截图（含提示句原文）
2. 桌面 `xjy-check.json`
3. 桌面 `xjy-logs.zip`

成功时只需要：

1. 升级前后底部 `总版本` 的截图
2. 升级后的 `xjy-check.json`（`verdict.isR2Client` 应为 `true`）

详细的界面文案对照、错误码反推方法、升级成功的判定标准，都在 `03-after-click.md`。
