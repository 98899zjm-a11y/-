本文替代同目录下 12:08 之前生成的 a15 版说明中所有"候选包摘要"部分；文件本身的"员工五步 / 主机步骤 / 失败处理"仍适用。

## 一、本批修复了什么（两个真实缺陷）

### 1. TREE_CHANGED 完整树含未声明空目录

现象：1.6.2 → 1.7.0 升级在引擎已经提交、文件逐字节一致之后，仍被判失败并弹出"安装或升级未完成"。

根因：`verifyInstalled` 复查用 `allowMutable=false`，可放行目录集合来自**备份之前**的采集；而备份阶段（`nativeContext.prepare()`）会在安装树里新建
`.xjy-initial-upgrade/<uuid>/data-backup/files/…` 与 `.xjy-patches/<hash>/<uuid>/data-backup/files/…` 下的空目录（工作室数据/images、工作文档、报价图片、程序设置/Dictionaries、程序设置/blob_storage/…），外加 `resources/NVIDIA Corporation(/umdlogs)` 这条 GPU 日志空链。

修复：`exactTree` 的目录判定改为两条受控放行——已批准的 GPU 路径链（`emptyDirectoryAlwaysAllowed`）与可写历史前缀下的**空**目录（`emptyMutableDirectoryAllowed`）。文件级 rows 比较一行未动：未知目录、非空可变目录、任何多出/缺失/摘要变化的文件仍然拒绝。

### 2. UNEXPECTED_SOURCE_FILE 旧程序有未知可变资料

现象：真实 1.6.2 安装树里带三个签名目录之外的文件，升级直接停：
`resources/default_app.asar`、`resources/elevate.exe`、`Uninstall 鑫金源珠宝报价.exe`。

修复：a16 增加**确切路径**白名单（无前缀、无通配、三条固定名），只允许它们作为"旧程序携带的可变文件"存在；它们**不会**被复制进新程序目录。
