## 二、本批改了什么

### 2.1 上一批（C6）到底出了什么故障

**现场证据（两台机器时间一致）：**

- `guest-results\dialog-20261022-104400.json` —— 2026-10-22 10:44:00 抓到的两个窗口：
  - 标题「运行」（PID 5048）—— 后台 worker 执行窗口；
  - 标题「安装或升级未完成」（PID 5500）—— 产品自己的失败收据，正文三行：
    ```
    安装或升级未确认完成。请保留原程序、备份和错误记录。
    worker 退出码为 1，不等于 0
    安装或升级已停止：TREE_CHANGED 完整树含未声明空目录
    ```
- `guest-results\treechange-2026-10-22T02-44-14.json` —— 2026-10-22T02:44:14Z（= 10:44 +08，同一分钟）的树比对快照：
  声明目录 `declaredDirs 221`，实际目录 `actualDirs 230`，多出 `extraDirs 9`，其中`空目录 emptyDirs 7`。

**发生了什么事：** 升级流程在提交阶段做"完整树复查"时，发现目标目录里出现了若干**升级前并不存在、也没有被声明**的目录，于是按安全策略**主动停止**，弹出上面那个窗口。

**这算不算事故？** 不算数据事故 —— 产品按设计"宁停不猜"停住了，原程序、备份、日志都保留着；但**这是一次升级失败**，用户看到的就是"没升成功"。这也是它必须修的原因。

### 2.2 根因（为什么会误报）

升级开始前，引擎会对"可写的历史目录"做一次快照登记（`engine-tree-runtime170.cjs` 里 `captureMutable`，本包第 1531 行；扫描从第 1537 行开始，前缀白名单在第 1538 行）。问题在于：

- 快照**只登记当时就已经存在的目录**；
- 但升级/备份过程中，程序会在这些历史前缀下**新建空目录**（比如 `…/data-backup/files/工作室数据/images`）；
- 提交后复查（同一文件里 `exactTree`，第 178 行定义，遍历在第 186–191 行）又用"必须全部在快照里"的标准去卡 —— **新建的空目录天然不在快照里，于是被判成"未声明"**。

**这次多出来的 9 个目录（`extraDirs`）逐条如下（相对交付包根）：**

| 项目 | 值 |

**改法（只加了一条"空目录白名单"，没有放宽其他任何校验）：**

在文件第 37 行附近新增 `EMPTY_DIRECTORY_ALLOWLIST_170` 块：

```js
const emptyMutableDirectoryPrefixes = Object.freeze(['.xjy-initial-upgrade/', '.xjy-patches/', '员工本地设置/', '.xjy-employee-updates/']);
const emptyDirectoryAlwaysAllowed = name => approvedEmptyDirectory(name);
const emptyMutableDirectoryAllowed = name => emptyMutableDirectoryPrefixes.some(prefix => name.startsWith(prefix));
```

并把提交后复查的判定（本包第 189 行）从：

```js
requireValue(directories.has(relative), 'TREE_CHANGED', '完整树含未声明空目录');
```

改为：

```js
requireValue(directories.has(relative) || emptyDirectoryAlwaysAllowed(relative)
  || (emptyMutableDirectoryAllowed(relative) && (await io.readdir(file)).length === 0),
  'TREE_CHANGED', '完整树含未声明空目录');
```

**这条白名单的边界（很重要，不是"关掉校验"）：**

1. 只放行**空目录**（`readdir` 长度为 0）；
2. 只放行**可写历史前缀之内**的空目录（4 个前缀：`.xjy-initial-upgrade/`、`.xjy-patches/`、`员工本地设置/`、`.xjy-employee-updates/`）；
3. 非空的未登记目录**照样拒绝**（上表第 5 条那个 `blob_storage` 如果真是多出来且非空，仍然会 `TREE_CHANGED`）；
4. 前缀之外的未知目录**照样拒绝**；
5. 原有 GPU 日志空链白名单不变。

**与 a14 的差异范围：** 逐行比对（忽略行尾空白差异）**只有 2 处、共 12 行** —— 就是上面这个新增块和那一行判定条件。没有顺手改别的东西。

## 五、失败了怎么办（现场处置）

### 5.1 三条处置动作

1. **保留现场**：原程序目录、升级文件夹（含 `.xjy-*`）、错误弹窗原文、日志，一样都不要删、不要手工改；

| 弹窗/日志里看到的字样 | 含义 | 现场该怎么做 |
| --- | --- | --- |
| `TREE_CHANGED 完整树含未声明空目录` | a14 的已知缺陷（本批 a15 已修） | 保留现场，升级到 a15 包再试；不要手工删目录去"凑"通过 |
