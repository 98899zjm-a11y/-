### 2.2 修复一：升级收尾误报 `TREE_CHANGED`（a15 起生效）

**现象（C6 复验时）**：安装/升级跑到收尾复查，弹出「安装或升级未完成」，正文含：

```
安装或升级已停止：TREE_CHANGED 完整树含未声明空目录
worker 退出码为 1，不等于 0
```

产品按"宁停不猜"主动停止，原程序、备份、日志都保留 —— 不是数据事故，但**是一次升级失败**，用户看到的就是"没升成功"。

**根因**：备份阶段会在安装树内**新建空目录**（`.xjy-initial-upgrade\`、`.xjy-patches\` 下的 `data-backup\files\…`，以及 `resources\NVIDIA Corporation\umdlogs`），而收尾复查只认"备份前登记的目录清单"，新建的空目录天然不在清单里，于是被判成"未声明目录"并中断。

**修复规则（已在签名范围内）**：复查时只放行两类目录 ——

1. **已批准的 GPU 空目录链**（`resources\NVIDIA Corporation\…`）；
2. **可写历史前缀下的空目录**：`.xjy-initial-upgrade/`、`.xjy-patches/`、`员工本地设置/`、`.xjy-employee-updates/`。

**仍然拒绝**：前缀之外的未知目录、以及这些前缀内**非空**的未登记目录。这是"给已知合法产物开口子"，**不是关掉校验**。

### 2.3 修复二：catalog 之外的历史文件误报 `UNEXPECTED_SOURCE_FILE`（a16 起生效）

**现象**：在真实 1.6.2 安装树上跑升级，升级还没开始就被拒 —— 源树里有 3 个文件不在已签 catalog 内，被当成异常：

| 路径 | 字节数 | sha256（前 8 位） |
| --- | --- | --- |
| `resources/default_app.asar` | 110,862 | `0eb2491b…` |
| `resources/elevate.exe` | 107,520 | `9b1fbf0c…` |
| `Uninstall 鑫金源珠宝报价.exe` | 166,715 | `76e77817…` |

它们都不是用户数据，也不是被篡改的文件：前两个是 Electron 发行包自带件，第三个是旧安装器写入根目录的卸载器。

**修复规则（已在签名范围内）**：只放行这**三个确切路径**（不做前缀匹配、不做通配），并明确**只保留在备份树里、不复制进目标树**。换任何别的路径、哪怕只是同名不同目录，仍然拒绝。

1. **安装器"最终成功提示"未取到。** 核验阶段操作方终止了安装器 worker 进程（**退出码 -1**），所以没有抓到安装器自报成功的那一步。实际状态是：**引擎侧已 committed，应用可以正常启动**（主窗口标题「鑫金源 · 珠宝报价工作室」），升级结果由引擎事务与逐文件核验证明。

3. **断电式失败恢复本轮未做**，属明确非承诺，见 3.2。
4. **员工身份验收未通过**：本轮只交付员工补丁包，不宣称员工侧验收通过。
5. 生产侧本轮做了两项**人工准备**（删除根级 0 字节空目录、最小 ACL 收紧），见第四节；这两项不在产品自动流程内，换机器/重装需重新评估。

## 四、维护方操作（本轮生产侧的两项人工准备）

> 这两项是本次在**这台生产机**上由维护方手工做的准备工作，**不是产品自动流程**。换机、重装、重跑升级前必须重新评估，不要以为"包里已经带了"。

### 4.1 删除安装根下的两个 0 字节空目录

- **删了什么**：`F:\自制软件\xjy-jewelry-offline\NVIDIA Corporation\umdlogs` 与 `F:\自制软件\xjy-jewelry-offline\NVIDIA Corporation`（两个都是 0 字节目录，无文件）。
- **为什么删**：引擎的空目录白名单只覆盖 `resources\NVIDIA Corporation\…` 这条链，**不覆盖安装在根级的同名链**；留着会被未声明目录判停，让升级在收尾阶段中断。
- **影响与回滚**：删的是空目录，不承载任何数据；需要恢复时手工重建同名目录即可，无其它副作用。

### 4.2 最小 ACL 收紧（可回滚）

- **先存档**：导出原 ACL 到 `s5-tools\prod-acl-original.json`（2026-10-22 14:47 导出，含 `F:\`、`F:\自制软件`、`F:\自制软件\xjy-jewelry-offline`、`F:\鑫金源珠宝资料` 的 SDDL）。
- **再收紧**：移除 `F:\` 上 `Authenticated Users` 的**写**权限（仅根目录上的显式 ACE，其余路径 0 处改动，因此叫"最小"收紧）。
- **回滚方法**（需管理员权限）：

  ```powershell
  .\s5-tools\prod-acl.ps1 -Phase rollback
  ```

  回滚按 `prod-acl-original.json` 里的 SDDL 还原，回滚后 `F:\` 根回到收紧前的状态。

## 七、失败处理与保留现场

### 7.1 三条动作

1. **保留现场**：原程序目录、升级文件夹（含 `.xjy-*`）、错误弹窗原文与截图、日志，全部原地不动，不删、不改、不清理。
2. **立即停手**：不连续重试、不关安全校验、不手工覆盖文件、不删"看起来多余"的目录去凑通过。
3. **走受信恢复入口**：用与当前版本匹配的受信入口恢复（`受信助手` / 包内恢复动作），**不要**把旧 `EXE` 拷贝回去冒充当次升级结果。

### 7.2 常见提示对照

| 提示字样 | 含义 | 处理 |
| --- | --- | --- |
| `TREE_CHANGED 完整树含未声明空目录` | 旧缺陷，a15 起已放行已知空目录 | 保留现场，改用 a16 完整包再试；**不要**手工删目录 |
| `UNEXPECTED_SOURCE_FILE` | 源树有 catalog 外文件；旧缺陷，a16 已按精确路径放行那 3 个 | 换 a16 包再试；其它未知文件仍会拒绝，按要求核对来源 |
| `EXISTING_HOST_DATA 已存在主机资料，首次安装停止` | 在已有账套的机器上跑了首次安装 | 属正常保护，不是故障：改用「一键升级」 |
| `UNSUPPORTED_SOURCE_VERSION` / `KNOWN_INSTALL_INVALID` | 源版本已经是目标版本，无需再升 | 正常保护：直接启动软件核对右下角版本，不要重跑 |
| `PROGRAM_IN_USE` / 程序正在使用 | 程序或业务窗口没退干净 | 托盘正常退出后重试 |
| `Bootstrap SHA256 mismatch` | 引导脚本自校验失败（文件被改或不完整） | **停止**，重新获取完整包，整包一起用 |
| `RECOVERY_REQUIRED` | 检测到上次未收尾的事务 | 走受信恢复入口，不要删状态文件 |
