## 四、员工补丁包需要整包分发

**`鑫金源珠宝1.7.0员工升级补丁.zip`（164,878,024 字节）必须整包分发，原因有三：**

1. **脚本按自身所在目录找组件**：`员工一键升级.cmd` / `一键升级.cmd` 会在同目录下找 `安装组件\native-delivery-170.ps1` 等上层组件，并对其做**固定 sha256 自校验**。缺组件或组件被替换 → 直接报 `Bootstrap SHA256 mismatch` 并停止。
2. **拆开分发的等价物是"未签名的零件"**：哈希表里的 sha256 只对**完整文件**成立；单个脚本或单个内部 ZIP 拷来拷去，无法再与已签候选对齐，出了问题无法追溯。
3. **线上/离线传输会截断大文件**：164MB 级别文件经微信、U 盘、邮件转发容易传残缺。**必须以 sha256 校验通过为"收到完整"的唯一标准**（对照本清单第三节第 6 行），不要用"能解压"当标准。

**分发要求（对维护方）：**

- 发送**整个 zip 原包**，不要解压后只发其中几个文件；如需解压使用，也要**整个文件夹一起**交给员工，不能只给某个 `.cmd`。
- 员工侧只解压到**一个完整文件夹**里使用，**不要**把脚本单独拖到桌面双击。
- 员工**不要运行 `首次安装主机.cmd`**（那是主机建账套用）；员工只用「一键升级」或 `员工一键升级.cmd`。
- 收到后先核对 sha256，再使用。

**为什么不是只发 `native-package.zip`？**
`native-package.zip`（781,517,174 字节 / 3,293 文件）是**签名归档整体**，用于留档、复核与主机侧完整升级；员工过渡期用 164MB 的补丁包更轻、更快。两者都**不可拆分使用**。

# 2) 逐条比对 SHA256SUMS.txt
Get-Content .\delivery-170-a15\SHA256SUMS.txt |
  Where-Object { $_ -match '^[0-9a-f]{64}  ' } |
  ForEach-Object {
